PowerScribe Report Exporter v0.24

Extract the ZIP and run PowerScribeReportExporter.exe. No installer,
PowerShell, Python, or AutoHotkey is required on the workstation.
Close the old exporter / Review Reports AHK before using this version.
The launcher stays compact and uses a dark night appearance.
Type case numbers directly; there are no up/down buttons. Options,
Copied text, and Details expand the window only when opened.

The running timer shows minutes and seconds for total time and the current step.

EVERYDAY USE

1. With the exporter open, close any Compare Report Revisions window. Click the starting case row
   you want to export in PowerScribe's worklist.
2. In the exporter, type First case and Last case, then press Go or Enter.
   These numbers label consecutive exported cases and set the count;
   they do not select numbered rows in PowerScribe.
3. On success, the comparison text is copied and the website opens.
   Choose Paste, then Analyze reports. Ctrl+V in the report box also works.

Automatic keeps fast key input but allows 750 ms for the first source-study
switch and at least 500 ms thereafter BEFORE opening its comparison. A selected
row/enabled reporting window does not mean the next report has loaded yet.
Delayed copies can add input settling. Custom case timing is preserved.
There is no filename prompt. Each run gets a new file in Documents\Report
comparisons by default. Options lets you change that folder or speed.
Open comparison file and Open save folder appear after the run.
Notepad opens by default for a new setup; you can turn it off in Options.
Existing saved on/off preferences are kept. A backup file is always saved.

COPIED TEXT

After exporting, Copied text appears above Options. It is hidden until
a run has saved complete pairs. Expand it to see the full comparison input.
Use Copy again whenever another app has replaced your clipboard.
The text stays available while this exporter is open, even if copying
fails. A stopped run also makes its saved complete pairs available here.
If a later run has no usable complete pairs, the previous text remains;
check the export date and case labels shown above it.
After closing the exporter, use the saved .for-comparison.txt backup.

STOPPING OR TROUBLESHOOTING

Use Stop, Numpad *, or Ctrl+Shift+F12 (the available shortcut is shown
when running). Completed captures are kept if a run stops.

Details shows what was saved, where it stopped, the error, and what to
try next. The same information is saved as a .run-summary.txt file.
Prepare remaining cases sets the remaining range in this launcher only.
You must close the comparison and select the matching starting row in
PowerScribe yourself, then Go. Resumed results are saved in a new file.
Check earlier saved results before deciding which row to resume from.

IF WORKLIST FOCUS CANNOT BE REMEMBERED

1. Expand Options and click Remember worklist (F8).
2. Click the first case row in PowerScribe. Press F8 while PowerScribe
   is active, then return to the exporter.
3. Confirm Worklist remembered, then Go.

This worklist capture lasts for this exporter session. Remember it again
when PowerScribe restarts or its layout changes. If F8 is rejected,
Details / the status message explains the Windows focus problem.

IF THE REPORT CLICK LANDS IN THE WRONG PLACE

In Options, choose Capture report click (optional). With the comparison
open, point inside the attending report body and press F8. Close the
comparison and select your starting worklist row before exporting.
Your existing saved report-click coordinates are retained on upgrade.
Moving the comparison window is normally fine. Resizing it, rearranging
panes, or changing display scaling can put the click in the wrong place.
Capture the report click again and check a short range after those changes.
The exporter cannot guarantee correct pane selection for every layout.

Only complete pairs enter the .for-comparison.txt file used by the
website. Pending/unavailable entries remain in the original capture;
Details lists their source numbers. The extractor never uploads reports.

Start with a short range and check report contents and order locally.
Automated checks use synthetic reports, not the UAB workstation.
See README.md for technical details and limits.

RETRYING A STOPPED RUN
The exporter remembers the worklist control while you are selecting a row in
PowerScribe, before Go or Continue takes focus. Keep the exporter open while
selecting the requested case. Continue stays available even if detection fails;
click it once. The readiness message identifies the control, not the case number,
so select the exact requested case in the same worklist and order.

Recoverable interruptions now show a Paused dialog while keeping saved reports.
Close Compare Report Revisions, select the requested case in the SAME worklist
and order, then click Continue. PowerScribe is brought forward and a fresh
capture starts at that case. After a saved case, it asks for the next case so
the saved pair is not duplicated. Finish means the final pair is already saved.
Stop is always available. A disk/save error still ends the run.

Supported report controls are read directly, bypassing Ctrl+C and the clipboard.
Both text and focused control must remain stable. Unsupported controls and very
long reports use the clipboard fallback. Clipboard text is accepted only when its update number and owner remain
stable across the read. A changing clipboard is reread, without another Ctrl+C
or comparison reopen. A controlled replay of v0.18 showed that this race can
duplicate the first saved pair despite correct visible navigation. This is not
yet confirmation of what happened on the hospital workstation.

Every saved pair is checked against its captured text. Details includes the new
.capture-checks.csv log: source labels and run-specific equality tokens, with no
report text or patient identifiers. If cases 1 and 2 are wrong, keep this log
with the ordinary progress log to identify capture versus saving errors.

If the first two full report pairs match when captured, the exporter first closes
and reopens that SAME comparison once in a fresh session. There is no extra Down,
row click or case-number change. It saves the new pair and continues if the
repeat resolves. An unresolved match pauses before saving the second. If different reports are
open, leave that comparison OPEN and choose "Retry open reports". It rereads
this case without reopening or moving the worklist and needs no worklist detection.
If the wrong study is selected, close the comparison, select the requested row,
and choose "Reselect case". Choose "Identical linked reports" only if they are
distinct studies with intentionally identical reports. It does not automatically reopen,
delete linked reports or guess that an extra Down is safe.

The launcher clears remembered worklist/capture/cancellation state after a stopped
or failed attempt. Select the intended first case row again, then Go. Preserve
Details and the text-free progress log if it still stalls; the root cause of the
reported first-case problem is not yet established on a hospital workstation.
